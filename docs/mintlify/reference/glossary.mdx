## Glossary

## Proxy

The RAWFRAME proxy intercepts HTTP/HTTPS traffic between a client and upstream server. It supports HTTP/1.1 plaintext proxying and HTTPS CONNECT tunneling with optional TLS interception.

## Scope

A scope defines which destinations a connection is allowed to reach. RAWFRAME uses default-deny scope enforcement, where only explicitly allowed destinations are permitted.

## CONNECT Tunneling

A mechanism for intercepting HTTPS traffic. The client establishes a CONNECT tunnel to the upstream server through the proxy, after which RAWFRAME relays raw TCP bytes between the client and upstream.

## TLS Interception

Opt-in feature that terminates TLS at the RAWFRAME local CA, decrypts the traffic, and re-encrypts it for the upstream. Requires explicit local CA trust configuration.

## Findings

Passive analysis results generated by the `rawframe-analysis` rule engine. Each finding carries severity, confidence, a triggering field or marker, impact description, and remediation guidance. Findings carry stable fingerprints and redacted evidence.

## TrafficEntry / TrafficRecord

A structured record of captured network traffic. Stores method, host, port, headers, body (if persisted), lifecycle state, timing metadata, and optional intruder/Repeater origin metadata.

## Session

A contiguous period of traffic capture associated with a project. Sessions can be restored from the SQLite database with redacted content.

## Project

A persistent container for one or more sessions and their associated traffic data, rules, and configuration.

## Repeater

A workbench for resending intercepted requests to upstream servers with optional modifications. Supports HTTP/1.1 and HTTP/2 connections with verified TLS.

## Intruder

A security testing workbench that sends fuzzed requests with multiple strategies (Sniper, Battering Ram, Pitchfork, Cluster Bomb) and bounded concurrency, rate, and duration limits.

## Redaction

The process of replacing sensitive header values with `<redacted>` during storage. Controlled by the `SENSITIVE_HEADERS` configuration and `persist_sensitive_headers` policy.

## ALPN (Application-Layer Protocol Negotiation)

A TLS extension that allows the client and server to negotiate the application protocol (e.g., `h2` for HTTP/2, `http/1.1` for plaintext) during the handshake.

## Pseudo-headers

HTTP/2 structured header fields with the `:` prefix (e.g., `:method`, `:authority`, `:path`). Managed through `rawframe_core::h2` conversion utilities.
