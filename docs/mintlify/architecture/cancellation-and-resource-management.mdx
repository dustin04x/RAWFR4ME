## Cancellation and resource management

## Bounded concurrency

- **Proxy**: max concurrent connections governed by a Tokio `Semaphore` (`max_connections`, default 128). Excess sockets are closed.
- **CONNECT tunnels**: separate tunnel semaphore bounds relays that outlive the upgraded client connection.
- **Repeater**: bounded concurrency limit with owned semaphore permits; the command channel, cancellation map, and task set are bounded.
- **Intruder**: maximum 8 concurrent workers; rate gate spaces starts using a monotonic deadline; rate limit 20 requests/second.
- **WebSocket**: 64 concurrent tunnels (separate semaphore).
- **Decoder**: 16 steps maximum, 8 MiB input/output maximum.

## Timeouts

| Component | Default timeout | Description |
| --- | --- | --- |
| Connect | 10 s | Upstream connection handshake timeout. |
| Response-header | 30 s | Wait for upstream response headers. |
| Idle | 60 s | Terminate a silent connection after this duration. |
| Interception | 120 s | Pending interception timeout before forward/drop. |
| WebSocket idle | 300 s | No frame activity for this duration. |
| Intruder duration | 1800 s (30 min) | Absolute duration ceiling. |

## Cancellation mechanisms

- **`CancellationToken` per execution** — each Repeater and Intruder execution has
  its own cancellation token.
- **`Shutdown` command** — signals all services via watch channel; waits for
  in-flight work (up to 5–8 s), then aborts remaining tasks.
- **`Ctrl+C`** — immediate emergency exit from the TUI; the process exits and
  the port becomes available quickly.
- **Paused runs** — an Intruder run that is paused keeps its queue and resumes
  without re-sending completed indices.

## Graceful shutdown

1. Signal shutdown on all services via watch channel.
2. TUI exits (confirmation if unsaved edits or paused requests).
3. Wait for proxy/Repeater/Intruder to finish their in-flight work (up to 5 s),
   then abort remaining tasks.
4. Storage worker closes the database with `WAL checkpoint`.
5. Database file permissions restored; process exits.

## Resource limits

- Bodies: 2 MiB request, 2 MiB response.
- Connections: 128 max concurrent.
- Queues: event bus 4096, command channel 32.
- Database: 512 MiB ceiling.
- Pipeline: 16 steps, 8 MiB input, 8 MiB output.
- Intruder: 16 positions, 16 payload lists, 512 payloads per list, 4096 bytes per payload, 2048 generated requests.
